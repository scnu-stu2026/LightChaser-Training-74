# 作品名称
舵机角度控制器
## 1. 功能概述
一句话说明做什么；列出 3~5 条主要功能。
1.串口角度控制，接收 0~180 的指令，拒绝 abc、200、90.5、空行等非法输入
2.PWM 舵机驱动：TIM2_CH1输出 50Hz PWM，0.5/1.5/2.5ms 对应 0°/90°/180°
3.OLED 状态显示：显示 MODE:AUTO/UART、CMD、PWM、LED；非法帧显示 ERR
4.LED 有效指令执行：AUTO 每步翻转一次，UART 每条有效指令翻转一次；非法指令不翻转
5.AUTO 脱机 + UART 接管：上电不接 PC 也能按序列循环；有效指令切 UART；10s后无有效指令切换为 AUTO；AUTO 中非法指令暂停 ERR 后再继续。

## 4. 实现思路
- 系统框图（文字或图片）
串口助手
   │ USB-TTL
   ▼
USART1_RX(PA10) → 1 字节中断 → 缓冲区 → 行组装 → 严格解析
                                                      │
                         ┌────────────────────────────┼────────────────────────────┐
                         │ 合法                        |
                                                    auto模式                             非法                       
                         ▼                                                         ▼                          
               mode = UART                                              不改 PWM、不翻 LED                
               TIM2_CH1(PA0) 50Hz PWM                                        AUTO 中暂停                      
               → MG90S 转到目标角
                         │
                         ├─ LED 翻转一次
                         ├─ OLED 更新 MODE/CMD/PWM/LED
                         └─ 串口回传（可选）

上电默认 AUTO：0→45→90→135→180→135→90→45→0，每 1.5s 一步
UART 10s 无有效指令 → 回 AUTO
- 主循环 / 状态机怎么组织
串口字节 → 缓冲区→ feed_line_byte() → parse_angle()
        → handle_valid() / handle_invalid() (合法、非法）
        → mode_tick()（AUTO/UART 调度）
        → ui_tick()（OLED 刷新、ERR 超时）
- 通信协议（如串口指令/返回格式；没用到可删）
90\n|	合法	|转到 90°
0\n / 180\n|	合法|	两端角度
45 \n|	合法|	前后空格允许
abc\n|	非法|	不是数字
200\n	|非法|	超范围
90.5\n	|非法|	小数
90abc\n|	非法|	数字后还有垃圾字符
空行 \n	|非法	|没有数字
非法处理：
不改变 PWM；
不翻转 LED；
OLED 显示 ERR，约 0.8s 后恢复；
AUTO 中暂停 AUTO，ERR 结束后重新等 1.5s 再走下一步；
UART 中不重置 10s 计时。

## 6. 遇到的问题与解决
| 问题 | 现象 | 原因 | 解决 |
|------|------|------|------|
问题	现象	原因	解决
OLED API 不匹配	|编译报 implicit declaration of |OLED_Clear/OLED_ShowString/OLED_Refresh_Gram	实际移植的是 keysking CH1116 framebuffer 驱动，没有这三个旧函数	改为 OLED_NewFrame()、OLED_PrintString()、OLED_ShowFrame()
缺少 i2c.h	编译报 i2c.h: No such file or directory	当前工程把所有初始化生成在 main.c，没有单独的 i2c.c/i2c.h	改为 #include "main.h" + extern I2C_HandleTypeDef hi2c1;；不复制旧 i2c.c
回调放错位置	|串口收不到数据，LED 不翻|	回调被放进 assert_failed() 的 USER CODE 6 里，且被 #ifdef USE_FULL_ASSERT 包住，默认不编译|	把 HAL_UART_RxCpltCallback / HAL_UART_ErrorCallback 移到文件作用域的 USER CODE 4
发两个字母灯不翻	|发 A 灯亮，发 AB 看起来没动	|HAL_GPIO_TogglePin 是奇偶翻转，2 次翻转回到原状态|最终把 LED 从“每字节翻”改为“每合法帧翻”
舵机不转|LED/OLED 正常，舵机无反应|未共地

## 7. 测试结果
- 测了什么、结果如何、有没有已知缺陷
串口口接收 发送 90\n、0\n、180\n、abc\n、200\n	合法帧执行，非法帧不动作
OLED 显示	观察 MODE/CMD/PWM/LED 与 ERR 恢复	通过：显示与指令一致，ERR 约 0.8s 恢复
LED 回执	10 条合法 / 10 条非法 / AUTO 3 步	合法翻、非法不翻、AUTO 每步翻
AUTO 脱机	不接 USB-TTL 上电	通过：按 0→45→90→135→180→135→90→45→0 循环，1.5s/步
UART 接管	AUTO 中发 90\n	通过：立即切 MODE:UART，停 AUTO
10s 回退	UART 中停发 10s	通过：回 MODE:AUTO，从 0 重新循环
非法指令	AUTO/UART 中发 200\n、abc\n	通过：不动作、不翻灯、ERR；AUTO 暂停后继续
已知缺陷 / 可改进：
开环控制：OLED 的 CMD 是目标角度，不是实测角度；实际角度靠指针/量角器验证，若要真反馈需加电位器。
半帧超时：实现了行缓冲和粘包处理，但未加入 80ms 半帧超时；后续可加 last_byte_tick 防止半帧污染下一帧。
OLED 刷新较慢：100kHz 全屏刷新约 100ms；已用 ui_dirty + 50ms 限频，后续可提高 I2C 到 400kHz。
